# Каталог находок: как обнаружить и как закрыть

Каждый класс описан так, чтобы его можно было проверить командой и закрыть диффом.
Классы 1–7 взяты из реального аудита Django-сервиса на одном VPS (октябрь 2026) и
обобщены; остальные — типовые для веб-сервисов без выделенного ИБ.

## 1. Патч-долг и «pre-CVE» слепая зона

**Как найти.** Сравнить версии из lockfile с последними релизами и их changelog:

```
uv export --frozen --no-dev --no-hashes > r.txt && pip-audit -r r.txt
pip index versions gunicorn        # что есть в реестре
```

Отдельно прочитать разделы Security в changelog каждого компонента периметра
(веб-сервер приложения, reverse proxy, фреймворк) за последние 6 месяцев. Причина:
уязвимость может быть опубликована вендором до присвоения CVE, и тогда сканеры
зависимостей её не видят.

**Как закрыть.** Поднять версию до последней патченной, зафиксировать пол в lockfile,
перезапустить сервис, проверить `--version` на хосте (а не в локальном venv).

**Почему важно.** Реальный случай: gunicorn 23.0.0 внутри диапазона request
smuggling, исправленного в 26.1.0; `pip-audit` по 26 пакетам печатал «no known
vulnerabilities».

## 2. Секреты уезжают на сервер вместе с деплоем

**Как найти.** Прочитать команду передачи в деплой-скрипте: что именно пакуется и
что исключено.

```
grep -n "tar\|rsync\|--exclude" scripts/deploy.sh
ls -l .env .env.* 2>/dev/null
```

`gitignore` не защищает: скрипт везёт рабочее дерево, а не индекс git.

**Как закрыть.** `--exclude=.env --exclude='.env.*'` в архиве; на сервере секреты
только в `EnvironmentFile` с правами `600` и владельцем-сервисом; проверить, что
файл не появился в каталоге приложения после деплоя.

## 3. HTML/разметка из пользовательского ввода в мессенджер или шаблон

**Как найти.** Искать отправку с `parse_mode` (HTML/Markdown) и подстановки без
экранирования:

```
grep -rn "parse_mode" . --include=*.py
grep -rn "html.escape\|escape(" . --include=*.py | head
```

Проверить руками: имя, контакт, комментарий, текст сообщения клиента идут в текст
уведомления как есть?

**Как закрыть.** `html.escape()` на каждую подстановку либо отправка уведомлений
владельцу как plain text (`parse_mode=None`). Для шаблонов автоэкранирование уже
работает; проблема только в ручной сборке строк.

**Почему важно.** Два последствия сразу: подмена вида сообщения (социальная инженерия
против владельца) и молчаливая потеря уведомления — Telegram вернёт 400 на
незакрытом теге, а код это просто залогирует.

## 4. Отсутствие HSTS и неполные security-заголовки

**Как найти.**

```
curl -sI https://host/ | egrep -i "strict-transport|content-security|x-frame|x-content-type|referrer"
```

**Как закрыть.** Включить поэтапно: `Strict-Transport-Security: max-age=300`, через
неделю `max-age=31536000; includeSubDomains`, `preload` — только после того, как
уверены во всех поддоменах. CSP вводить в режиме `Report-Only`, затем ужесточать.

## 5. Нет ограничения частоты на записывающих ручках

**Как найти.** Найти все POST-эндпоинты (заявка, загрузка, вход, сообщение) и
проверить наличие троттлинга в коде и на периметре:

```
grep -rn "ratelimit\|throttle\|RateLimit" . --include=*.py | head
```

**Как закрыть.** Счётчик на IP + ключ (сессия, контакт) с окном 1–10 минут; на
уровне reverse proxy — лимит на `/upload` и `/login`. Отдельно лимит размера тела
запроса и количества файлов.

## 6. Привязка объектов по введённому пользователем контакту

**Как найти.** Прочитать логику «найти мои заказы по email/телефону». Если
сопоставление идёт по строке, которую ввёл человек, — чужой контакт даёт доступ к
чужой истории.

**Как закрыть.** Привязка только по одноразовому коду, отправленному на этот контакт,
либо по подписанному токену из письма. Строка контакта остаётся поисковым ключом, но
не доказательством владения.

## 7. `Content-Type` при отдаче файлов берётся из загрузки

**Как найти.** Место, где файл отдаётся клиенту: заголовок из БД, из `mimetypes` по
расширению, или из самого файла.

**Как закрыть.** Всегда `Content-Type: application/octet-stream` и
`Content-Disposition: attachment; filename*=UTF-8''…` для пользовательских файлов;
inline-просмотр — только для явного белого списка (pdf, jpg, png) и с
`X-Content-Type-Options: nosniff`.

## 8. Загрузка файлов: путь, размер, исполнение

**Как найти.** Проверить: имя файла санитизируется (path traversal, `..`, юникод),
есть ли лимит размера, лежит ли каталог загрузок внутри дерева, откуда сервер может
исполнять код, доступен ли файл по прямой ссылке без авторизации.

**Как закрыть.** Хранить вне web-root, отдавать только через view с проверкой прав и
подписанным токеном; генерировать имя самому; отдельный том с `noexec,nosuid`.

## 9. Админка и вход: путь, брутфорс, MFA

**Как найти.** `curl -sI https://host/admin/` (код ответа), число попыток входа в
логах, наличие fail2ban jail именно на этот путь, есть ли MFA у staff-аккаунтов.

**Как закрыть.** Переименовать путь, ограничить по IP на reverse proxy, MFA для
staff, fail2ban на 401/403, алерт на успешный вход с нового ASN.

## 10. Агентский контур: консоли, MCP, ключи

**Как найти.** На сервере `ss -lntp` — что слушает не на loopback. В конфигах MCP и
агента — литералы ключей. У токенов агента — TTL и scope. У кодирующего агента —
write-доступ к прод-чекауту.

**Как закрыть.** Всё агентское — только loopback или WireGuard; ключи в env с
правами 600; отдельная идентичность на агента; прод-чекаут только на чтение, выкладка
отдельным шагом с ревью.

## 11. Вредоносная зависимость и подмена пакета

**Как найти.** `pip freeze` на незнакомые имена рядом с вашими; `*.pth` и
`sitecustomize.py` в venv должны быть объяснимы; проверка `npm ls --all` на дубли.

**Как закрыть.** Установка только из lock с хешами, без `--extra-index-url`; агентам
запрещено ставить пакеты в прод-venv; алерт на новые зависимости в диффе.

## 12. Кривая конфигурация хоста

**Как найти.**

```
ssh host 'sshd -T | egrep "permitrootlogin|passwordauthentication|x11forwarding"'
ssh host 'ss -lntp; sudo ufw status verbose; sudo fail2ban-client status'
ssh host 'systemctl cat <service> | egrep "User|NoNewPrivileges|ProtectSystem|PrivateTmp"'
ssh host 'ls -l /etc/<app>.env; sudo -n true'
```

**Как закрыть.** `PermitRootLogin no`, `PasswordAuthentication no`,
`X11Forwarding no`; сервис под отдельным пользователем с
`NoNewPrivileges=yes`, `ProtectSystem=strict`, `PrivateTmp=yes`; ufw «deny incoming,
allow 22/80/443»; fail2ban с jail на ssh и на логи приложения; unattended-upgrades
для security-обновлений.

## Шаблон отчёта

```markdown
# Аудит безопасности <проект>, <дата>

Стек: <язык/фреймворк> <версия> · <сервер> · <reverse proxy> · <БД>
Публичные поверхности: <список>

## Сводка
P1: n · P2: n · P3: n. Самый вероятный сценарий атаки: <одна строка>.

## Находки
### F1 · P1 · <название>
- Где: <файл:строка / хост>
- Доказательство: `<команда>` → `<вывод, 1–3 строки>`
- Почему эксплуатируемо: <одно предложение>
- Исправление: <дифф или команда>
- Откат: <как вернуть>
- Проверка после: <команда, которая покажет, что закрыто>

## Что проверено и в порядке
<список с командами>

## Не проверено и почему
<нет доступа / требует решения владельца>

## Приложение: сырые выводы
<заголовки curl, версии, ss -lntp>
```
